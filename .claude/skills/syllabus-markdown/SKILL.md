# syllabus.md を作る

公式シラバス（Web・PDF など）を読み込み、[`docs/SYLLABUS_FORMAT.md`](../../../docs/SYLLABUS_FORMAT.md) の形式の `courses/<course_id>/syllabus.md` を作ります。
公式シラバスに書かれていること（概要・目標・各回・評価）は**写し**、書かれていないこと（実施要件・教材の作り方）は**教員に聞いて**埋めます。推測で埋めません。

## 1. 最初に確かめること

次をそろえます。足りないものは教員に聞きます。

| 項目 | 例 | 使い道 |
|---|---|---|
| 公式シラバスの入手元 | URL、PDF・Word のパス、貼り付けた本文 | 採録の元 |
| 科目 ID | `basic_math`（半角英数字と `_`） | フォルダ名・`course_id` |
| 既存の `syllabus.md` の有無 | `courses/<id>/syllabus.md` | あれば**更新**（採録部分以外の教員の記述を消さない） |

## 2. 読み込む

- **URL**：WebFetch で本文を取得する。ログインが必要なページは取得できないので、PDF の保存か本文の貼り付けを頼む。
- **PDF**：Read で読み、**`pdftotext -layout <PDF> -` の出力と照らし合わせる**。PDF によっては、Read で読むと漢字が見た目の同じ別の文字（康熙部首 U+2F00〜U+2FDF など。例：「工」→「⼯」）に化ける。写す前に Unicode NFKC で正規化し、化けた文字が残っていないことを確かめる（正規化は「表記ゆれの修正」には当たらない）。表が改ページをまたぐときは、回と行の対応がずれていないか確かめる。
- **Word など**：テキストに変換してから読む。変換できないときは本文の貼り付けを頼む。

読み取った内容から、次を拾い出します。見つからない項目は**作らず**、§4 で教員に聞く（聞けない項目は `## 未確定事項` に書き、報告にも挙げる）。

- 科目名・年度・学期・単位数・対象・担当教員・実施形態・授業時間
- 授業の概要・目的
- 到達目標（番号つきなら番号ごと）
- 各回の授業計画（回ごとのテーマと内容、事前・事後学修）
- 成績評価の方法と配点
- 教科書・参考書
- 備考（履修条件など）

## 3. 写す（採録）

[`templates/syllabus.md`](../../../templates/syllabus.md) を元に書き始め、公式シラバスの記述を次のように写します。

- `# コース概要`・`# 達成目標`・`# 授業計画` の各回・`# 評価方法` の配点：**文言は原文どおり**に写す。言いかえ・要約・表記ゆれの修正はしない。
  - ただし、形式に合わせるための**機械的な整形**はしてよい：箇条書きにする、区切りを `: ` にする、数字・`%` を半角にする（例：「毎回の演習問題　５０％」→ `- 毎回の演習問題: 50%`）、NFKC 正規化。
  - 到達目標は原文の数と言い回しのまま写す（「〜する」でも「〜できる」に直さない。項目も足さない）。補足したいときは別の箇条で「（補足）」と書く。
- 採録した**節ごと**に、直後に出典を1行書く：「（上記は公式シラバス（YYYY-MM-DD 取得）の「〇〇」を採録したもの。）」
- front matter の `source` に URL かファイル名と取得日を書く。取得日は、Web なら取得した日、ファイルなら作業した日（PDF に印刷日があれば併記）。
- `course_name` は科目名だけにする（「-3【工学部】」のようなクラス番号・所属の表記は `# 備考` に残す）。`term` は原文の表記のまま。
- 授業計画は1回につき `## 第NN回: タイトル`（2桁）。タイトルに `:` が含まれていてもそのまま書く（`第NN回: ` の後ろ全体がタイトル）。各回の中身は、原文の欄ごとに1行の箇条書きにする（例：`- 授業内容: …`、`- 事前学修: …`、`- 事後学修: …`）。回数が `total_lessons` と一致することを確かめる。
- 公式シラバスにだけある項目（題目、関連科目、履修条件、他学部の受け入れ、使用言語、実務経験など）は `# 備考` の `## 公式シラバスのその他の項目` に写す。
- 公式シラバスに `# 授業の実施要件` に当たる欄（開講方法、フィードバックの方法など）があれば、該当する下位の節に**採録**し、足りない点だけ §4 で聞く。
- 学内限定のリンク（ログインが必要な URL、学内の短縮 URL）は写さず、写さなかったことを報告する。
- 配点の合計が 100% にならない、回数が合わない、などの不整合は**直さず**、`# 備考` の `## 未確定事項` に書いて教員に知らせる。

## 4. 聞いて埋める

公式シラバスで埋まらない次の項目は、教員に**まとめて**質問して埋めます（AskUserQuestion が使えるなら、選択肢つきで最大4問ずつ）。教員が「おまかせ」と言った項目だけ、下の既定値を使い、その節の末尾に「（教員がおまかせとしたため、既定値を使った。）」と注記します。「必ず聞く」項目に答えが得られないときは、プレースホルダ（`（未定）`）を置いて `## 未確定事項` に書きます。

| 節 | 聞くこと | 既定値（おまかせのとき） |
|---|---|---|
| front matter `duration_minutes` | 1回の授業時間 | （必ず聞く） |
| front matter `target`・`# 対象学生` | 学年・学部、人数の規模、予備知識のばらつき、苦手の傾向 | （必ず聞く） |
| `# 前提知識` | どこまで既知として扱うか | （必ず聞く） |
| `## 実施形態` | 対面／オンライン／オンデマンド／ハイブリッド、教室の制約 | front matter の `delivery_mode` |
| `## 1回の授業の型` | 毎回の基本の流れ | 振り返り10分 → 講義と演習を交互に → 確認問題5分 → まとめ5分 |
| `## 出席と提出` | 出席の取り方、提出物の出し方 | （聞かずに空欄にしない。必ず聞く） |
| `## フィードバック` | 結果をいつどう返すか（公式シラバスにあれば採録したうえで、具体的な返し方を聞く） | 次回の冒頭で全体に講評 |
| `## 配慮` | 配慮が必要な学生への対応の原則（個人の情報は書かない） | 大学の窓口の依頼に従う、とだけ書く |
| `## 毎回作る教材` | slides / handout / worksheet / exercise / lecture_script のどれを作るか | `slides, handout, worksheet, exercise` |
| `## スライドの方針` | 枚数、情報量、フォント | 10〜15枚、1枚1メッセージ、図を中心、原ノ味 |
| `## ワークシートの方針` | 問題数、解答版 | 4〜6問、解答版あり、記入欄は答えの長さで変えない |
| `## 確認問題の方針` | 問題数、採点方法 | 5問・4択、手採点または AMC |
| `## 表記の約束` | ベクトル・行列・用語の書き方 | 科目に応じた案を【提案】と付けて書き、`## 未確定事項` に「表記の約束の確認」を入れる |
| `## 著作権と出典` | 教科書の扱い | 教科書の問題文は転載しない、外部の図は使わない |
| `# 評価方法` の `## 生成 AI の利用ポリシー` | 学生が課題・試験で生成 AI を使ってよい範囲 | （必ず聞く） |
| `# 教材の作り方` の `## 生成 AI の使い方` | 教材作りに生成 AI を使う範囲と、人が確かめる点 | 下書きに使ってよい。解答はすべて検算し、図は目で確かめる |

## 5. 書き出して点検する

1. `courses/<course_id>/syllabus.md` に書き出す（既存ファイルがあれば、教員が書いた節を残したまま更新する）。
2. [`docs/SYLLABUS_FORMAT.md`](../../../docs/SYLLABUS_FORMAT.md) の「チェックリスト」を1つずつ確かめる。
3. 教員に次を報告する：採録した節と出典、聞いて埋めた節、既定値を使った節、`## 未確定事項` に書いた不整合。

## してはいけないこと

- 公式シラバスにない内容（各回のテーマ、配点、到達目標）を**作らない**。足りなければ聞く。
- 学生個人の情報（氏名・学籍番号・成績・配慮の具体）を書かない。
- 公式シラバスの文章を「読みやすく」書き換えない（採録は原文どおり。補足は別に書く）。
- 次の段階（各回の `lesson_plan.md`）は、教員が求めたときだけ `lesson-plan` スキルで行う。
