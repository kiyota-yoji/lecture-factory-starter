# lesson_plan.md の標準フォーマット

`lesson_plan.md` は、1回の授業の**設計書**です。「何を、なぜ、どの順で、どの教材で教えるか」を書きます。授業回のフォルダに1つ置きます（`courses/<科目ID>/<NN>/lesson_plan.md`）。

- [`syllabus.md`](SYLLABUS_FORMAT.md) の授業計画・実施要件・教材の作り方から作ります。
- スライド・ワークシート・確認問題などの教材は、この文書から作ります。教材と食い違ったときは、`lesson_plan.md` を直してから教材を直します。
- 作り方の手順は [WORKFLOW.md](WORKFLOW.md)、白紙の雛形は [`templates/lesson_plan.md`](../templates/lesson_plan.md) です。AI エージェント（Claude Code・Codex・Antigravity など）では `lesson-plan` スキルで作れます（[WORKFLOW.md](WORKFLOW.md)）。
- 記入例：[`courses/basic_math/07/lesson_plan.md`](../courses/basic_math/07/lesson_plan.md)

---

## 1. 全体の形

```markdown
---
（front matter：YAML）
---

# 授業概要
# 前後回との接続
# 到達目標
# 主要概念
# 前提知識
# 授業の流れ
# 強調したいポイント
# つまずきやすい点
# 問いかけ設計
# スライド設計
# ワークシート設計
# 確認問題の設計
# 演習課題
# 元資料との対応
# 教員レビュー項目
# 未確定事項
```

- 見出しの名前と順番はこのとおりにします。任意の節は、使わなければ見出しごと省略します。
- `lesson_plan.md` は**設計書**です。授業後の記録（出席者数・正答率・反省）は書き足さず、別のメモ（例：`notes.md`）にします。

## 2. front matter

| キー | 必須 | 内容 | 例 |
|---|---|---|---|
| `course_id` | ◎ | `syllabus.md` と同じ科目 ID | `basic_math` |
| `lesson_no` | ◎ | 回の番号 | `7` |
| `lesson_title` | ◎ | 回のタイトル（`syllabus.md` の授業計画と同じ） | `微分法の基礎` |
| `outputs` | ◎ | この回で作る教材（[教材の種類](SYLLABUS_FORMAT.md#教材の作り方推奨)の名前） | `[slides, handout, worksheet, exercise]` |

- `lesson_title` は `syllabus.md` の授業計画の見出しと同じ文字列にします（スライドの題名で句読点を全角にするなどの違いは構いません）。
- `references` の例：`syllabus.md`、教科書の章・ページ、前回の `lesson_plan.md`、参考にした論文・記事（出典として書けるもの）。
| `duration_minutes` | ○ | 授業時間（省略時は `syllabus.md` の値） | `100` |
| `delivery_mode` | ○ | この回の実施形態（省略時は `syllabus.md` の値） | `face_to_face` |
| `prev_lesson` | ○ | 前の回の番号（初回は省略） | `6` |
| `next_lesson` | ○ | 次の回の番号（最終回は省略） | `8` |
| `lesson_date` | 任意 | 実施日 | `2026-05-25` |
| `references` | 任意 | 参照する資料（`syllabus.md`、教科書の章、過年度資料など） | `["syllabus.md", "教科書 第3章 pp.40–52"]` |

## 3. 各節の書き方

### `# 授業概要`（必須）

この回の中心テーマを2〜4文で書きます。

### `# 前後回との接続`（必須）

```markdown
## 前回から
## 今回の位置づけ
## 次回へ
```

冒頭の振り返りと、最後の次回予告の根拠になります。

### `# 到達目標`（必須）

「〜できる」の形で合計3〜6項目。授業中や確認問題で**確かめられる**表現にします。節の末尾に、対応する `syllabus.md` の達成目標の番号を「（対応する達成目標：1・3）」のように書きます。学生の理解度に差が大きい科目では、3段に分けても構いません。

```markdown
## 必達目標（全員）
## 理解目標（できれば全員）
## 発展目標
```

### `# 主要概念`（推奨）

この回のキーワードを列挙します。数学系の科目では扱う公式を LaTeX で、それ以外の科目では用語と1行の定義（例：「内挿：手元のデータがある範囲の内側で推定すること」）で書きます。

### `# 前提知識`（推奨）

この回で使う既習事項と、それを扱った回（`syllabus.md` の授業計画の回）を書きます。前の回の `lesson_plan.md` がなくても、授業計画から書けます。

### `# 授業の流れ`（必須）

**時間の表**で書きます。時間は開始からの分で、区間の合計が授業時間に一致するようにします。

```markdown
| 時間 | 内容 | 教材 |
|---|---|---|
| 0–5 | 前回の振り返り | スライド 2 |
| 5–25 | 平均変化率 → 微分係数 | スライド 3–7 |
| 25–40 | 演習（問1・問2） | ワークシート |
| …  | … | … |
| 95–100 | まとめ・次回予告 | スライド 13 |
```

- 1行に講義と演習を混ぜず、別の行に分けます（講義が続く長さを表から確かめられるように）。
- 表のすぐ下に、時間の合計の検算を1行書きます（例：`5 + 15 + 10 + … = 100`）。

表の後に、時間が押したときに**削る順**と、**削らないもの**を書きます。講義だけが20分を超えて続かないよう、受講者が手か頭を動かす活動（演習・問いかけ・口頭での問い）をはさみます。

### `# 強調したいポイント`（推奨）

学生に必ず持ち帰ってほしいことを1〜3項目。まとめのスライドの元になります。

### `# つまずきやすい点`（推奨）

よくある誤解・計算ミス。注意のスライドや、確認問題の誤答の選択肢の元になります。

### `# 問いかけ設計`（任意。話し合い・記述が中心の科目では推奨）

受講者に考えて書いてもらう問い（「考えてみよう」など）ごとに、問いの文・ねらい・時間・回収のしかた（紙・LMS・口頭）・演習課題とのつながりを書きます。

### `# スライド設計`（`outputs` に `slides` があれば必須）

- 枚数の目安と、各スライドの**1行メッセージ**の一覧（授業の流れの順）。演習の時間に出す合図のスライドも番号に含めます。1行メッセージは、スライドの `\lfsmessage{...}` に入れる文です（`\lfsmessage` を使わないスライドは、スライドの題を書きます）。
- 図の一覧：`figures/` に分けて置く図（グラフ・図形など）ごとに、何を示す図か・描き方（TikZ で描く／自作の画像）を書きます。箱と矢印で文字を並べただけのスライドの配置は、一覧に挙げなくて構いません。外部の図は使いません。

### `# ワークシート設計`（`outputs` に `worksheet` があれば必須）

問題ごとに、ねらい・形式（計算・穴埋め・記述）・正解・記入欄の大きさを書きます。記入欄の大きさは、途中式を書くのに必要な広さで決め、**同じ種類の問では同じ高さ**にします（答えの長さに合わせて枠を変えると、答えが推測できるため）。小問ごとに高さが違う場合は「(1)(2) 2.6cm、(3)(4) 3.4cm」のように書きます。

### `# 確認問題の設計`（`outputs` に `exercise` があれば必須）

問題ごとに、確かめる到達目標（番号か短い名前）・正解・誤答の選択肢とそのねらい（どんな誤解を拾うか）を書きます。正解の選択肢だけが長い・詳しいと、長さで答えが分かってしまうので、選択肢の長さをそろえます。ねらいが読み取れない既存の誤答は「（ねらい不明）」と書き、`# 未確定事項` で見直しを提案します。

### `# 演習課題`（任意）

授業外の課題の内容・分量・提出方法（具体的な締切日は運用側で決める）。

### `# 元資料との対応`（既存の資料から作り直すときは必須）

原本のページと新しいスライドの対応の表。書き方は §4.2。

### `# 教員レビュー項目`（推奨）

教材ができたあとに人が確かめる観点のチェックリスト。数学系なら解答の検算・図の正しさ、事例や数値を扱う科目なら一次資料での確認・スライドと付録の出典の一致、どの科目でも時間配分。

### `# 未確定事項`（任意）

決まっていないことのチェックリスト。

## 4. 教材がすでにある回の書き起こし

### 4.1 このリポジトリの形の教材がある回

既存の教材から `lesson_plan.md` を書き起こすときは、教材の内容（スライドの順番・問題・正解）をそのまま書き写し、`references` に元にした教材のファイル（`slides.tex` など）も挙げます。前の回の `lesson_plan.md` がなければ、`syllabus.md` だけで前後回との接続を書いて構いません。教材と `syllabus.md` が食い違う点や、教材の誤りに気づいた点は、教材も `lesson_plan.md` も勝手に直さず、`# 未確定事項` に書いて教員に知らせます。

### 4.2 学外の形式の既存の資料（PowerPoint・Google スライド・PDF など）から作り直す回

原本の置き場所・点検・記録は [SOURCE_MATERIALS.md](SOURCE_MATERIALS.md)、手順はスキル `existing-materials` にあります。`lesson_plan.md` は次のように書きます。

- `references` に `source/SOURCES.md`（と公開用の写し `source/<略号NN>_public.pdf`）を挙げる。原本（`source/original/`）は Git の外なので挙げない。
- 内容と順番は原本のまま書き起こす。`# スライド設計` は原本のページの順に書く。
- `# 元資料との対応` に、原本のページ → 新しいスライドを表で書く。

  | 原本 p | 原本の見出し | スライド | 扱い | メモ |
  |---|---|---|---|---|
  | 8 | LINEの例で考える | 7 | 書き換え | ロゴを削除し、サービス名を文字で |
  | 26 | Google Analytics | 25 | 模式図に置き換え | 画面写真 → TikZ の模式図 |
  | 35 | 演習課題 | 37 | 書き換え | 字数・締切は syllabus の方針に |
  | — | — | 13 | 追加 | 「考えてみよう」（syllabus の授業の型） |

  扱いは「そのまま／書き換え／模式図に置き換え／分割／削除／追加」のどれか。原本にない内容（**追加**）は、`syllabus.md` の授業の型に合わせる最小限にとどめ、教員レビュー項目に挙げる。
- 原本の誤り（一次資料で確かめて違っていた年号など）は、作り直す教材では直し、`# 元資料との対応` のメモと `SOURCES.md` の `## 事実の確認` に書く。
- 原本と `syllabus.md` の食い違いのうち、方針に関わるもの（評価・課題の分量・授業の型）は `# 未確定事項` に書く。

## 5. 書かないこと

- **学生個人の情報**（氏名・学籍番号・成績・提出状況）は書きません。
- 教科書の問題文は転載せず、番号とページで指します。
- 授業後の記録・運用のログは書きません（別のメモへ）。

## 6. チェックリスト

- [ ] `outputs` の `slides`・`worksheet`・`exercise` に対応する設計の節がある（`handout` は `slides` から自動で作られ、`lecture_script` は授業の流れとスライド設計に従うので、専用の節は不要）
- [ ] 既存の資料から作り直す回は、`# 元資料との対応` があり、追加・削除したところが分かる
- [ ] 学生個人の情報が入っていない
