# 既存の授業資料の置き場所と扱い

これまで PowerPoint・Google スライド・Keynote・Word・PDF などで作ってきた授業資料を、このリポジトリの形（LaTeX のスライド・確認問題と `lesson_plan.md`）に作り直すときの約束です。
作り直しの手順は、スキル `existing-materials`（[`.agents/skills/existing-materials/SKILL.md`](../.agents/skills/existing-materials/SKILL.md)）にあります。例は [`courses/ai_business/08/`](../courses/ai_business/08/) です。

> 既存の資料には、ロゴ・画面写真・他の人の図・学生の情報など、**公開してはいけないもの**が混ざっていることがよくあります。
> このリポジトリはそのまま公開できる状態を保つため、**原本は Git に入れず、確かめた記録と、消すべきものを消した写しだけを入れます。**

---

## 1. 置き場所

既存の資料は、作り直す回のフォルダの `source/` に置きます。

```text
courses/<科目>/<NN>/
├─ source/
│  ├─ original/                 ① 原本（Git に入れない）
│  │  ├─ <略号NN>_original.pdf   例：aib08_original.pdf
│  │  └─ <略号NN>_original.pptx  元の形式のファイルも並べてよい
│  ├─ <略号NN>_public.pdf        ② 公開用の写し（任意・Git に入れる）
│  └─ SOURCES.md                ③ 記録（必ず作る・Git に入れる）
├─ lesson_plan.md
├─ slides.tex …                  作り直した教材
```

| | 置くもの | Git | 決まり |
|---|---|---|---|
| ① `source/original/` | 受け取ったままの原本 | **入れない**（`.gitignore` で除外済み） | 手を加えない。ファイル名は半角英数字にする（例：`aib08_original.pdf`） |
| ② `source/<略号NN>_public.pdf` | 原本から第三者の素材・運用上の情報を消した PDF | 入れる | 作るかどうかは任意。作るときは名前の末尾を必ず `_public.pdf` にする（この名前の PDF だけが Git に入る） |
| ③ `source/SOURCES.md` | 原本の出どころ、ページごとの点検の結果、消したもの・直したもの | 入れる | 形は [§4](#4-sourcesmd-の書き方) |

- 略号は、確認問題の ID と同じ科目の略号（`ai_business` → `aib`、`basic_math` → `bm`）と回の番号です。
- 1つの資料が**複数の回**にまたがるとき（全回まとめのスライド、過年度のシラバスなど）は、科目のフォルダの `courses/<科目>/source/` に同じ形で置き、各回の `SOURCES.md` からそのファイルを指します。
- `source/` の中の `.tex` は、一括ビルド（`tools/build_all.lua`）の対象になりません。

### 置いてはいけないもの（`original/` にも置かない）

`original/` は Git に入りませんが、手元のフォルダの同期（Dropbox・OneDrive など）や、設定の誤りで外に出ることがあります。次のものは、**リポジトリのフォルダの中に置かず**、学内の決められた場所で管理してください。

- 学生の情報を含むもの：提出物、名簿、成績、座席表、出席の記録、配慮の内容、学生の顔や名前が写った写真・画面
- 教科書・市販の問題集のスキャン（使うときは書名・章・ページで指す）
- 他の人が作った資料（共同で担当する先生の資料など）。作者の了解と、作り直したものを公開してよいかを確かめてから、③の記録に了解の内容を書いて使う

## 2. 点検すること（ページごと）

原本を1ページずつ見て、次のものを探します。文字だけでなく、**画像の中**（ロゴ・画面写真・写真の中の文字）も見ます。`pdfimages -list` で画像のあるページが分かります。

| 種類 | 例 | 公開用の写し（②） | 作り直すとき |
|---|---|---|---|
| ロゴ・商標の図柄 | サービスのアイコン、企業のロゴ | 消す | 使わない。サービス名を文字で書く |
| 画面写真（スクリーンショット） | アプリ・Web サービス・分析ツールの画面 | 消す | TikZ で描いた**模式図**にし、「〇〇の画面の例（模式図）」と書く |
| 写真・イラスト | Web やストック素材の画像、出どころの分からない図 | 消す | 使わない。必要なら TikZ で描き直す |
| 他の人の図表・グラフ | 報告書・記事の図をそのまま貼ったもの | 消す | 数値を一次資料で確かめ、出典を書いて自分で描き直す |
| 引用 | 記事・書籍の文章 | 残してよい（出典があるとき） | 必要な範囲にとどめ、出典を書く |
| 運用上の情報 | 提出の締切、教室、LMS の名前、クラス、小テストの時間 | 残してよい（学生の情報でなければ） | `syllabus.md` の方針に合わせて書き直すか、消す |
| 個人の名前 | 自分以外の教員・学生・ゲストの名前 | 消す | 書かない（本人の了解があるときを除く） |
| 年号・数値・事例 | 「2012年 スタンプ導入」「利用者数◯億人」 | 残す（原本の記録として） | **一次資料で確かめる。** 誤りは直して③に書く。確かめられないものは使わない |

自分で描いた図・自分で書いた文章は、そのまま使って構いません。迷うものは「消す・使わない」側に倒し、③に「確認が必要」と書いて教員に知らせます。

## 3. 公開用の写し（②）の作り方

`tools/redact_pdf.py` で作ります。Python と PyMuPDF が必要です（この作業をする人だけ。教材のビルドには要りません）。

```bash
python3 -m pip install pymupdf
```

画像の位置を確かめてから、消したいページの画像を消します。消した場所には灰色の枠と、ラベルの文字が入ります。

```bash
python3 tools/redact_pdf.py courses/ai_business/08/source/original/aib08_original.pdf --list
```

```bash
python3 tools/redact_pdf.py courses/ai_business/08/source/original/aib08_original.pdf courses/ai_business/08/source/aib08_public.pdf --images 8,9,10,12,18 --label "ロゴを削除"
```

- 消す理由ごとにラベルを変えたいときは、出力を次の入力にして何回かに分けて実行します（例は [`courses/ai_business/08/source/SOURCES.md`](../courses/ai_business/08/source/SOURCES.md)）。
- 画像になっていないもの（文字や図形で描かれたロゴ、個人の名前など）は、`--rect "ページ:x0,y0,x1,y1:ラベル"` で範囲を指定して消します（座標はページの左上からの pt）。
- 文書情報（作成者・作成ソフトなど）は消え、タイトルは `--title` で付け直せます。
- **作ったら必ず確かめる**：`pdfimages -list <公開用>.pdf` で画像が残っていないか、`pdftoppm -r 60 -png` で画像にして消し残し・消しすぎがないかを見ます。

Python を使えないときは、Ghostscript の `-dFILTERIMAGE` で**すべての画像**を消せます（消した場所の枠・ラベルは入りません。ロゴ以外に自作の画像もあるときは使えません）。

```bash
gs -o out_public.pdf -sDEVICE=pdfwrite -dFILTERIMAGE in.pdf
```

## 4. `SOURCES.md` の書き方

`source/SOURCES.md` は次の順に書きます。例：[`courses/ai_business/08/source/SOURCES.md`](../courses/ai_business/08/source/SOURCES.md)。

```markdown
# 第NN回 元資料の記録

## 元資料
| 項目 | 内容 |
|---|---|
| ファイル | `original/aib08_original.pdf`（Git の外） |
| 元の形式 | Google スライド → PDF に書き出し（35ページ・16:9） |
| 作成者 | 清田 陽司（自作） |
| 作成時期・使った年度 | 2025年度 |
| 他の人の素材 | ロゴ 3種、画面写真 1枚、出どころ不明の図 1枚 |
| 公開用の写し | `aib08_public.pdf`（作り方は下） |

## ページごとの点検
| p | 見出し | 第三者の素材 | 運用上の情報 | 確かめる事実 | 扱い |
|---|---|---|---|---|---|

## 公開用の写しの作り方
（実行したコマンドをそのまま）

## 事実の確認
| 原本の記述 | 確かめた結果 | 出典 | 作り直した教材での扱い |
|---|---|---|---|

## 未確定事項
```

- 「扱い」には、作り直した教材でどうしたか（そのまま／書き換え／模式図に置き換え／削除）を書きます。スライドとの対応は `lesson_plan.md` の `# 元資料との対応` に書きます（[LESSON_PLAN_FORMAT.md](LESSON_PLAN_FORMAT.md) §4）。
- 事実の確認は、一次資料（発表元の沿革・プレスリリース・統計など）で行い、確かめられなかったものは「確かめられない」と書きます。

## 5. チェックリスト

- [ ] 原本は `source/original/` にあり、`git status` に出てこない
- [ ] 学生の情報・教科書のスキャンを、リポジトリのフォルダの中に置いていない
- [ ] `SOURCES.md` に、出どころ・ページごとの点検・事実の確認がある
- [ ] 公開用の写しを作ったなら、`pdfimages -list` で画像が残っていないことと、画像にして消し残しがないことを確かめた
- [ ] 作り直した教材に、ロゴ・画面写真・出どころの分からない画像が入っていない
- [ ] 原本の誤りを直したところは、`SOURCES.md` と `lesson_plan.md` の両方に書いた
