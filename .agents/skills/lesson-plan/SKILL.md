# lesson_plan.md を作る

科目の `syllabus.md` から、1回分の授業の設計書 `courses/<course_id>/<NN>/lesson_plan.md` を作ります。形式は [`docs/LESSON_PLAN_FORMAT.md`](../../../docs/LESSON_PLAN_FORMAT.md) に従います。
教材（スライド・ワークシートなど）は**まだ作りません**。教材は、教員が設計を確認したあとで `lesson-materials` スキルで作ります。

## 1. 最初に確かめること

| 項目 | 例 |
|---|---|
| 科目 ID と回 | `basic_math` の第07回（複数回も可） |
| `courses/<course_id>/syllabus.md` があるか | なければ先に `syllabus-markdown` スキルを勧める |
| 既存の `lesson_plan.md` があるか | あれば**更新**する（教員が書いた記述を消さない） |
| 使ってよい資料 | 教科書の章・ページ、前回までの教材、教員のメモ |
| 教材がすでにあるか | あれば「書き起こし」：教材の内容をそのまま書き写し、食い違いは直さずに `# 未確定事項` へ（[LESSON_PLAN_FORMAT.md](../../../docs/LESSON_PLAN_FORMAT.md) §4） |

## 2. 読む

1. `syllabus.md` 全体。特に次の部分：
   - `# 授業計画` の**この回**と**前後の回**の見出し・内容
   - `# 達成目標`（この回の到達目標の元）
   - `# 授業の実施要件` の `## 1回の授業の型`（授業の流れの骨組み）
   - `# 教材の作り方`（`outputs` と各教材の方針）
   - `# 評価方法`（確認問題・演習の扱い）
2. 前の回の `lesson_plan.md` があれば、その `# 前後回との接続` の `## 次回へ` と、`# 強調したいポイント`。なければ、前の回の教材（`slides.tex` など）か、`syllabus.md` の授業計画から判断する。
3. 教員が指定した参考資料（教科書は章・ページの確認だけにとどめ、問題文を写さない）。

## 3. 書く

[`templates/lesson_plan.md`](../../../templates/lesson_plan.md) を元に、次の順で書きます。

1. **front matter**：`course_id`・`lesson_no`・`lesson_title`（授業計画の見出しと同じ）・`outputs`（`# 教材の作り方` の `## 毎回作る教材` を既定に、この回の例外を反映）・`prev_lesson`/`next_lesson`。
2. **授業概要**：授業計画のこの回の内容を、2〜4文の授業の主題にまとめる。
3. **前後回との接続**：前後の回の内容から書く。
4. **到達目標**：`# 達成目標` のどれを具体化するかを意識して、確かめられる「〜できる」で合計3〜6項目（3段に分けるときも合計で数える）。節の末尾に「（対応する達成目標：1・3）」のように、`syllabus.md` の達成目標の番号（上から数えた順）を書く。
5. **主要概念・前提知識**：前提知識には、それを扱った回の番号を添える。
6. **授業の流れ**：`## 1回の授業の型` を骨組みに、時間の表で書く。
   - 区間の合計を `duration_minutes` に**ぴったり**合わせる（足し算で確かめる）。
   - 講義だけが20分を超えて続かないよう、演習・問いかけ（口頭の問いを含む）をはさむ。話し合い・記述が中心の科目では `# 問いかけ設計` も書く。
   - 1行に講義と演習を混ぜない。表の下に合計の検算（`5 + 15 + … = 100`）を書く。
   - 表の後に「削る順」と「削らないもの」を書く。
7. **強調したいポイント・つまずきやすい点**：つまずきは、確認問題の誤答の選択肢に使える具体的な誤解として書く。
8. **教材ごとの設計**：`outputs` にある教材だけ書く。
   - `slides` → `# スライド設計`：各スライドの1行メッセージを流れの順に、図の一覧（何を示すか・TikZ で描く）。演習の時間の**合図のスライド**（「演習：ワークシート 問1・問2」など）も番号に含め、`# 授業の流れ` のスライド番号と一致させる
   - `worksheet` → `# ワークシート設計`：問題ごとのねらい・形式・記入欄
   - `exercise` → `# 確認問題の設計`：問題ごとの到達目標・正解・誤答の選択肢とねらい
9. **教員レビュー項目・未確定事項**：決めきれないことは推測で埋めず、`# 未確定事項` に書く。

## 4. 点検して報告する

1. [`docs/LESSON_PLAN_FORMAT.md`](../../../docs/LESSON_PLAN_FORMAT.md) の「チェックリスト」を確かめる（特に時間の合計）。
2. 数学・計算を含む回は、ワークシート・確認問題に書いた**正解を検算**する（`python3` の標準ライブラリだけで書ける。分数は `fractions.Fraction`、行列の積は2重ループで十分）。事例・数値を扱う回は、使う数値・事例に**一次資料の出典**があるかを確かめ、ないものは使わないか `# 未確定事項` に書く。
3. 確認問題の選択肢の長さがそろっているか（正解だけが長くないか）を確かめる。
4. 教員に、到達目標・授業の流れの要点・`# 未確定事項` を短く報告し、「この設計で教材を作ってよいか」を確かめる。

## してはいけないこと

- `syllabus.md` にないテーマを、この回の主題にしない（足すときは教員に確かめる）。
- 教科書の問題文・図を写さない（番号とページで指す）。
- 学生個人の情報や、授業後の記録を書かない。
- 教員の確認なしに、教材（`.tex`）の作成まで進まない。ただし、教員が最初から「授業計画を作って、そのまま教材も」と頼んだ場合は、それを確認とみなしてよい（その場合も、教材に進む前に授業計画の要点を報告する）。
